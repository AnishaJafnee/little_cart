# LittleCart – Mini Checkout & Browser Test Suite

> A simple, functional single-page checkout application built with React + Vite, with an automated Playwright browser test suite.  
> Built as part of a hackathon challenge.

---

## 1. Project Title

**LittleCart – Mini Checkout and Browser Test Suite**

---

## 2. Project Overview

LittleCart is a minimal, clean online checkout page that lets a customer browse two stationery products, manage their cart, enter their name, and place an order. It is built entirely on the client side — no backend, database, or payment gateway.

---

## 3. Problem Statement

Build a complete, functional single-page checkout application that:
- Displays products with prices.
- Manages a shopping cart (add, remove, quantity controls).
- Collects a customer name.
- Validates input before order placement.
- Prevents duplicate order submissions.
- Is tested with automated Playwright browser tests.

---

## 4. Features

| Feature | Description |
|---|---|
| Product listing | Two synthetic products with fixed prices |
| Add to Cart | Adds product; increments quantity if already in cart |
| Quantity controls | + / − buttons; minimum quantity enforced at 1 |
| Remove item | Remove button per line item |
| Dynamic totals | Line total and order total update instantly |
| Customer name | Required text field with inline validation |
| Place Order | Validates cart and name before processing |
| Duplicate protection | Button disabled during and after submission |
| Order confirmation | Unique LC-XXXXXX reference, name, and total |
| Validation messages | Clear inline and banner error messages |
| Responsive layout | Works on desktop and mobile |
| Playwright tests | 3 automated browser test cases |
| HTML test report | Generated by Playwright |

---

## 5. Technology Stack

| Layer | Technology |
|---|---|
| UI Framework | React 18 |
| Build Tool | Vite 5 |
| Language | JavaScript (ES Modules) |
| Styling | Vanilla CSS |
| Browser Testing | Playwright |
| Version Control | Git |
| Hosting | Vercel |

> **No backend, database, payment gateway, authentication, or external APIs are used.**  
> All product data is synthetic and stored locally in `src/data/products.js`.  
> Order processing is simulated on the client side.  
> Duplicate submission prevention is implemented on the client side only.

## 10. Installing and Running Playwright

```bash
# Install both Chromium and Firefox browser binaries
node node_modules/@playwright/test/cli.js install chromium
node node_modules/@playwright/test/cli.js install firefox

# Run all automated tests (both browsers)
npm test
# or directly:
node node_modules/@playwright/test/cli.js test

# Run tests for one browser only
node node_modules/@playwright/test/cli.js test --project=chromium
node node_modules/@playwright/test/cli.js test --project=firefox

# Run tests with the browser visible (headed mode)
node node_modules/@playwright/test/cli.js test --headed

# Open the HTML test report after tests complete
npm run test:report
# or
node node_modules/@playwright/test/cli.js show-report
```

---

## 11. Browser Testing Instructions

1. Ensure the project is installed (`npm install` done).
2. Install the Chromium browser for Playwright: `npx playwright install chromium`
3. Run `npm test` — Playwright automatically starts the Vite dev server.
4. After tests complete, open the HTML report: `npx playwright show-report`
5. Screenshots of any failures are saved to `screenshots/`.

## 16. Known Limitations

- No persistent storage — cart and order data are lost on page refresh.
- Duplicate protection is client-side only. A server-side implementation would be required for production use.
- Order references are random and not guaranteed to be globally unique.
- No real payment processing — the checkout is for demonstration only.
- Product catalogue is hardcoded (2 products). No CMS or admin panel.

---

## 17. Assumptions

- Users access the app from a modern browser (Chrome, Edge, Firefox).
- All pricing is displayed in Indian Rupees (₹) only.
- Product prices are fixed and do not change.
- The app does not need to work offline.
- No accessibility audit beyond semantic HTML and ARIA labels was required.
